    Cslib.Algorithms.Lean.binSearch_eq_some_iff

    Let \(A = (a_0, \dots, a_{n-1})\) be an array of length \(n\) with entries in a linearly ordered type, with \(a_i \le a_j\) whenever \(i < j\). Let \(k\) and \(a\) be elements of that type and \(\ell\), \(h\) natural numbers. Lean core's array binary search for \(k\) in \(A\), with the strict order \(<\) as comparison and inclusive bounds \(\ell\) and \(h\), returns \(a\) if and only if \(a = k\) and there is an index \(i < n\) with \(\ell \le i \le h\) and \(a_i = k\).

    The requirement \(i < n\) reflects the implementation's clamping of an upper bound \(h \ge n\) to \(n - 1\).

    theorem binSearch_eq_some_iff {α : Type} [LinearOrder α] {as : Array α}
    (hs : as.Pairwise (fun a b => a ≤ b)) {k a : α} {lo hi : Nat} :
    as.binSearch k (fun x y => decide (x < y)) lo hi = some a ↔
      a = k ∧ ∃ i, ∃ h : i < as.size, lo ≤ i ∧ i ≤ hi ∧ as[i] = k

    DefinitionLower-bound search#✓fully proved

    Cslib.Algorithms.Lean.TimeM.lowerBound

    Given an array \(a = (a_0, \dots, a_{n-1})\) over a linearly ordered type and a key \(k\), lower-bound search maintains a half-open interval \([l, h)\) of indices, starting from \([0, n)\). While \(l < h\), it compares \(a_m\) with \(k\) at the midpoint \(m = l + \lfloor (h - l)/2 \rfloor\), charging one unit for this comparison, and continues with \([m + 1, h)\) if \(a_m < k\) and with \([l, m)\) otherwise. When \(l = h\) it returns \(l\).

    When \(a\) is sorted in nondecreasing order (or at least partitioned at \(k\): every entry before the returned index is \(< k\) and every entry from that index on is \(\ge k\)), the result is the first index \(i\) with \(k \le a_i\), or \(n\) if every entry is below \(k\). On an unsorted array the result is unspecified: for \(a = (2, 1)\) and \(k = 2\) the search returns \(2\), not the first index \(0\) with \(k \le a_0\).

    def lowerBound (xs : Array α) (key : α) : TimeM Nat Nat :=
  let rec loop (lo hi : Nat) (hlohi : lo ≤ hi) (hhi : hi ≤ xs.size) : TimeM Nat Nat :=
    if h : lo < hi then
      let mid := lo + (hi - lo) / 2
      have hmidhi : mid < hi := by
        dsimp [mid]
        omega
      have hmid : mid < xs.size := hmidhi.trans_le hhi
      do
        ✓
        if xs[mid] < key then
          loop (mid + 1) hi (by omega) hhi
        else
          loop lo mid (by omega) (hmidhi.le.trans hhi)
    else
      pure lo

    Cslib.Algorithms.Lean.TimeM.lowerBound_spec

    Let \(a = (a_0, \dots, a_{n-1})\) be an array over a linearly ordered type, sorted in nondecreasing order, let \(k\) be a key, and let \(\ell\) be the index returned by lower-bound search for \(k\) in \(a\). Then \(\ell \le n\), \(a_j < k\) for every \(j < \ell\), and \(k \le a_j\) for every \(j\) with \(\ell \le j < n\).

      (∀ j (_hj : (lowerBound xs key).ret ≤ j) (_hjs : j < xs.size), key ≤ xs[j])

    Cslib.Algorithms.Lean.TimeM.binarySearchFirst?

    Given an array \(a = (a_0, \dots, a_{n-1})\) over a linearly ordered type and a key \(k\), binary search for the first occurrence of \(k\) in \(a\) runs lower-bound search for \(k\) in \(a\), obtaining an index \(\ell\). If \(\ell < n\), it makes one further comparison, charged one unit, and returns \(\ell\) when \(a_\ell = k\) and no index otherwise; if \(\ell \ge n\), it returns no index without further cost.

    When \(a\) is sorted in nondecreasing order, the result is the first index \(i\) with \(a_i = k\), or no index when \(k\) does not occur in \(a\). On an unsorted array a present key can be missed and the result can be no index.

    def binarySearchFirst? (xs : Array α) (key : α) : TimeM Nat (Option Nat) := do
  let i ← lowerBound xs key
  if h : i < xs.size then
    ✓
    if xs[i] = key then
      return some i
    else
      return none
  else
    return none
