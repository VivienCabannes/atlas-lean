    InductiveStep relation of the stack machine#✓fully proved

    Cslib.IMP.StackMachine.Step

    Let \(P\) be a program, that is a list of instructions, and write \(a :: \sigma\) for the stack with top \(a\) above the stack \(\sigma\). A configuration \((pc, \sigma, s)\) steps to a configuration \(c'\) under \(P\) exactly when \(pc < |P|\) and, for the instruction at position \(pc\) of \(P\) (counted from \(0\)), one of the following holds, where \(s[x \mapsto v]\) is the state \(s\) with variable \(x\) set to \(v\).

    • \(\mathsf{push}\ n\): \(c' = (pc + 1, n :: \sigma, s)\).
    • \(\mathsf{load}\ x\): \(c' = (pc + 1, s(x) :: \sigma, s)\).
    • \(\mathsf{store}\ x\): \(\sigma = v :: \tau\) and \(c' = (pc + 1, \tau, s[x \mapsto v])\).
    • \(\mathsf{add}\), \(\mathsf{sub}\), \(\mathsf{mul}\): \(\sigma = a :: b :: \tau\) and \(c' = (pc + 1, r :: \tau, s)\), where \(r\) is \(b + a\), \(\max(b - a, 0)\) or \(b \cdot a\) respectively.
    • \(\mathsf{eq}\), \(\mathsf{le}\): \(\sigma = a :: b :: \tau\) and \(c' = (pc + 1, r :: \tau, s)\), where \(r\) is \(1\) if \(b = a\), respectively \(b \le a\), and \(r = 0\) otherwise.
    • \(\mathsf{not}\): \(\sigma = a :: \tau\) and \(c' = (pc + 1, r :: \tau, s)\), where \(r = 1\) if \(a = 0\) and \(r = 0\) otherwise.
    • \(\mathsf{and}\): \(\sigma = a :: b :: \tau\) and \(c' = (pc + 1, r :: \tau, s)\), where \(r = 1\) if \(b \ne 0\) and \(a \ne 0\), and \(r = 0\) otherwise.
    • \(\mathsf{jump}\ t\): \(c' = (t, \sigma, s)\).
    • \(\mathsf{jumpIfZero}\ t\): either \(\sigma = 0 :: \tau\) and \(c' = (t, \tau, s)\), or \(\sigma = (n + 1) :: \tau\) for some \(n\) and \(c' = (pc + 1, \tau, s)\).

    For binary instructions the top of the stack \(a\) is thus the right operand and the value below it \(b\) is the left operand.

    TheoremNo step past the end of the program#✓fully proved

    Cslib.IMP.StackMachine.no_step_of_length_le

    Let \(P\) be a program, that is a list of instructions, and let \((pc, \sigma, s)\) be a configuration with \(|P| \le pc\). Then the stack machine running \(P\) has no step from \((pc, \sigma, s)\) to any configuration, since there is no instruction at position \(pc\) to fetch.

    Hence the length of the code compiled from a command at base address \(0\) is a halt address for that code.

    DefinitionInstruction count of an arithmetic expression#✓fully proved

    Cslib.IMP.StackMachine.alen

    The instruction count \(\ell(a)\) of an arithmetic expression \(a\) is defined by recursion on \(a\): a constant or a variable has count \(1\), and if \(a\) is the sum, difference or product of \(a_1\) and \(a_2\), then \(\ell(a) = \ell(a_1) + \ell(a_2) + 1\).

    It is the number of stack-machine instructions generated when \(a\) is compiled.

    def alen : AExp → Nat

  | .var _ => 1
  | .add left right => alen left + alen right + 1
  | .sub left right => alen left + alen right + 1
  | .mul left right => alen left + alen right + 1

    DefinitionCompilation of commands#✓fully proved

    Cslib.IMP.StackMachine.compile

    The compiled code \(C_p(c)\) of an IMP command \(c\) at base program counter \(p\) is the list of stack-machine instructions defined by recursion on \(c\), where jump targets are absolute program counters and \(\ell\) denotes instruction counts: \(C_p(\mathbf{skip})\) is empty; \(C_p(x := a)\) is the code of \(a\) followed by the instruction store \(x\); \(C_p(c_1; c_2)\) is \(C_p(c_1)\) followed by \(C_{p + \ell(c_1)}(c_2)\). For the conditional \(\mathbf{if}\ b\ \mathbf{then}\ c_1\ \mathbf{else}\ c_2\), put \(q = p + \ell(b) + 1\) and \(r = q + \ell(c_1) + 1\); its code is the code of \(b\), then jump-if-zero to \(r\), then \(C_q(c_1)\), then jump to \(r + \ell(c_2)\), then \(C_r(c_2)\). For the loop \(\mathbf{while}\ b\ \mathbf{do}\ c_1\), put \(q = p + \ell(b) + 1\); its code is the code of \(b\), then jump-if-zero to \(q + \ell(c_1) + 1\), then \(C_q(c_1)\), then jump to \(p\).
