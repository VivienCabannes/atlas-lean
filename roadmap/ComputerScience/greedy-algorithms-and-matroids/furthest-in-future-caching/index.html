    DefinitionLegal cache transitions#✓fully proved

    Cslib.Algorithms.Lean.OfflineCaching.cacheLTS

    For a capacity \(k \in \mathbb{N}\), this is the labelled transition system whose states are lists of blocks (the cache contents, in any order) and whose labels are cache events. Write \(|C|\) for the length of a list \(C\), \(x :: C\) for \(C\) with \(x\) prepended, and \(C \setminus v\) for \(C\) with the first occurrence of \(v\) removed. There is a transition from \(C\) to \(C'\) labelled by a hit on \(r\) when \(r \in C\) and \(C'\) is a permutation of \(C\); labelled by a miss on \(r\) with no eviction when \(r \notin C\) and either \(k = 0\) and \(C\) and \(C'\) are both empty, or \(|C| < k\) and \(C'\) is a permutation of \(r :: C\); and labelled by a miss on \(r\) evicting \(v\) when \(k > 0\), \(r \notin C\), \(|C| = k\), \(v \in C\) and \(C'\) is a permutation of \(r :: (C \setminus v)\).

    @[expose] public def cacheLTS {α : Type u} [DecidableEq α] (capacity : Nat) :
    Cslib.LTS (List α) (CacheEvent α) where
  Tr before event after := match event with
    | .hit request => request ∈ before ∧ after.Perm before
    | .miss request none => request ∉ before ∧
        ((capacity = 0 ∧ before = [] ∧ after = []) ∨
          (before.length < capacity ∧ after.Perm (request :: before)))
    | .miss request (some victim) =>
        0 < capacity ∧ request ∉ before ∧ before.length = capacity ∧
          victim ∈ before ∧ after.Perm (request :: before.erase victim)

  | miss (request : α) (evicted : Option α)

    DefinitionFurthest-in-future caching#✓fully proved

    Cslib.Algorithms.Lean.OfflineCaching.furthestInFuture

    Given a capacity \(k\), a sequence of requested pages and an initial cache (a list of pages), the furthest-in-future manager serves the requests in order and returns the list of emitted cache events together with the final cache. A request for a page \(r\) already in the cache is a hit and leaves the cache unchanged. Otherwise it is a miss: if \(k = 0\), nothing is evicted and the cache becomes empty; if the cache holds fewer than \(k\) pages, nothing is evicted and \(r\) is added at the front; otherwise the manager evicts the cached page whose next occurrence among the later requests is furthest away (a page never requested again counts as infinitely far, and ties go to the page listed first in the cache), removes it and adds \(r\) at the front.

    public def furthestInFuture {α : Type u} [DecidableEq α]
    (capacity : Nat) (requests initialCache : List α) : List (CacheEvent α) × List α :=
  run capacity requests initialCache

    TheoremThe furthest-in-future manager produces legal traces#✓fully proved

    Cslib.Algorithms.Lean.OfflineCaching.furthestInFuture_legal

    Let \(k\) be a capacity, \(R\) a list of requested blocks and \(C\) a duplicate-free list of blocks of length at most \(k\). Let \(E\) be the events and \(D\) the final cache produced by the furthest-in-future manager with capacity \(k\) on \(R\) from the initial cache \(C\). Then \(E\) leads from \(C\) to \(D\) by legal cache transitions for capacity \(k\), the blocks requested by the events of \(E\) are, in order, exactly \(R\), and \(D\) is duplicate-free of length at most \(k\).

    theorem furthestInFuture_legal {α : Type u} [DecidableEq α]
    (capacity : Nat) (requests initialCache : List α)
    (hnodup : initialCache.Nodup) (hcapacity : initialCache.length ≤ capacity) :
    let output := furthestInFuture capacity requests initialCache
    (cacheLTS capacity).MTr initialCache output.1 output.2 ∧
      output.1.map (fun event => match event with
        | .hit request => request | .miss request _ => request) = requests ∧
      output.2.Nodup ∧ output.2.length ≤ capacity
    public def furthestInFuture {α : Type u} [DecidableEq α]
    (capacity : Nat) (requests initialCache : List α) : List (CacheEvent α) × List α :=
  run capacity requests initialCache

    TheoremOptimality of furthest-in-future caching#✓fully proved

    Cslib.Algorithms.Lean.OfflineCaching.furthestInFuture_min_misses

    Let \(k\) be a capacity, \(R\) a list of requested blocks and \(C\) a duplicate-free list of blocks of length at most \(k\). Let \(E'\) be any list of cache events that leads from \(C\) to some final cache by legal cache transitions for capacity \(k\) and whose events request, in order, exactly the blocks of \(R\). Then the furthest-in-future manager with capacity \(k\) on \(R\) from the initial cache \(C\) emits at most as many miss events as \(E'\) contains.

    Legal transitions may reorder the list representing the cache, so a competing trace need not keep the manager's order.

    theorem furthestInFuture_min_misses {α : Type u} [DecidableEq α]
    (capacity : Nat) (requests initialCache : List α)
    (hnodup : initialCache.Nodup) (hcapacity : initialCache.length ≤ capacity)
    (events : List (CacheEvent α)) (finalCache : List α)
    (hlegal : (cacheLTS capacity).MTr initialCache events finalCache)
    (hrequests : events.map (fun event => match event with
      | .hit request => request | .miss request _ => request) = requests) :
    (furthestInFuture capacity requests initialCache).1.countP
      (fun event => match event with | .hit _ => false | .miss _ _ => true) ≤
      events.countP (fun event => match event with | .hit _ => false | .miss _ _ => true)
