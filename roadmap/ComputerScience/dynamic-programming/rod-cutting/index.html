    DefinitionBottom-up rod cutting#✓fully proved

    Cslib.Algorithms.Lean.RodCutting.bottomUpCutRod

    Given prices \(p = (p_1, \dots, p_n)\) in an additive commutative monoid \(\alpha\) with a linear order, \(p_i\) being the price of a piece of length \(i\), bottom-up rod cutting fills a table \(r_0, \dots, r_n\) in increasing order by \(r_0 = 0\) and \(r_j = \max_{1 \le i \le j} (p_i + r_{j-i})\) for \(1 \le j \le n\), and returns \(r_n\). Its cost is the number of candidates \(p_i + r_{j-i}\) it evaluates, one for each pair \(1 \le i \le j \le n\).

    public def bottomUpCutRod {α : Type u} [AddCommMonoid α] [LinearOrder α]
    {n : Nat} (prices : Vector α n) : TimeM Nat α := do
  let table ← fillRows prices n le_rfl
  pure (table.get (Fin.last n))
    @[no_expose] private def fillRows {α : Type u} [AddCommMonoid α] [LinearOrder α]
    {n : Nat} (prices : Vector α n) :
    (count : Nat) → count ≤ n → TimeM Nat (Vector α (n + 1))
  | 0, _ => pure (Vector.replicate (n + 1) 0)
  | count + 1, hcount => do
      let table ← fillRows prices count (by omega)
      let best ← scanCuts prices table (count + 1) hcount count (by omega)
      pure (table.set (count + 1) best)

    Cslib.Algorithms.Lean.RodCutting.extendedBottomUpCutRod

    Let \(\alpha\) be an additive commutative monoid with a linear order, and let \(p_1, \dots, p_n \in \alpha\) be the prices of pieces of length \(1, \dots, n\) (the price vector's entry \(i - 1\) is \(p_i\)). The algorithm fills a revenue table \(r_0, \dots, r_n\) and a first-cut table \(s_1, \dots, s_n\) for the lengths \(j = 0, 1, \dots, n\) in increasing order: \(r_0 = 0\), and for \(j \ge 1\) it scans the candidates \(p_i + r_{j-i}\) for \(i = 1, \dots, j\) in increasing order of \(i\), starting from the candidate for \(i = 1\) and moving to a later candidate only when it is strictly larger than the current one. Then \(r_j\) is the largest candidate and \(s_j\) is the least \(i\) whose candidate equals \(r_j\). The result is the pair of tables, where \(r_j\) is the revenue vector's entry \(j\) and \(s_j\) is the cut vector's entry \(j - 1\), and the cost is one tick per evaluated candidate, so \(j\) ticks for length \(j\).

    public def extendedBottomUpCutRod {α : Type u} [AddCommMonoid α] [LinearOrder α]
    {n : Nat} (prices : Vector α n) : TimeM Nat (Vector α (n + 1) × Vector Nat n) :=
  fillRowsWithCuts prices n le_rfl
    @[no_expose] private def fillRowsWithCuts {α : Type u} [AddCommMonoid α]
    [LinearOrder α] {n : Nat} (prices : Vector α n) :
    (count : Nat) → count ≤ n → TimeM Nat (Vector α (n + 1) × Vector Nat n)
  | 0, _ => pure (Vector.replicate (n + 1) 0, Vector.replicate n 0)
  | count + 1, hcount => do
      let tables ← fillRowsWithCuts prices count (by omega)
      let best ← scanCutsWithIndex prices tables.1 (count + 1) hcount count (by omega)
      pure (tables.1.set (count + 1) best.1, tables.2.set count (best.2.val + 1))
