    DefinitionHolding a lock#✓fully proved

    Cslib.Databases.HoldsBefore

    Let \(s\) be a locked schedule, \(t\) a transaction, \(x\) a data item, \(m\) a lock mode and \(p\) a natural number. Transaction \(t\) holds a lock on \(x\) covering mode \(m\) just before position \(p\) of \(s\) when there is a position \(q < p\) at which \(s\) has a lock request by \(t\) on \(x\) in some mode \(m'\) that covers \(m\), and for no position \(r\) with \(q < r < p\) is the action of \(s\) at \(r\) a release of \(x\) by \(t\).

    def HoldsBefore (s : List (Action n X)) (t : Fin n) (x : X) (m : LockMode) (p : ℕ) : Prop :=
  ∃ q < p, (∃ m', s[q]? = some (.lock t x m') ∧ m'.Covers m) ∧
    ∀ r < p, q < r → s[r]? ≠ some (.unlock t x)
    inductive Action (n : ℕ) (X : Type*)
  /-- A read or a write. -/
  | op (o : Op n X)
  /-- Transaction `t` acquires a lock on `x` in mode `m`. -/
  | lock (t : Fin n) (x : X) (m : LockMode)
  /-- Transaction `t` releases its lock on `x`. -/
  | unlock (t : Fin n) (x : X)
deriving DecidableEq

    DefinitionSchedules covered by locks#✓fully proved

    Cslib.Databases.LocksCover

    A locked schedule \(s\) is covered by locks when every read or write is protected by a lock of its transaction: whenever \(s\) has at position \(p\) a read or write \(o\) by transaction \(t\) on item \(x\), just before position \(p\) transaction \(t\) holds a lock on \(x\) (acquired at an earlier position and not released since) whose mode covers the mode \(o\) requires, namely shared for a read and exclusive for a write; an exclusive lock covers both modes.

    def LocksCover (s : List (Action n X)) : Prop :=
  ∀ p o, s[p]? = some (.op o) → HoldsBefore s o.txn o.item o.access.mode p

    DefinitionSchedules that release every lock#✓fully proved

    Cslib.Databases.ReleasesLocks

    A locked schedule \(s\) releases its locks when every lock request is followed by a matching release: whenever \(s\) has at position \(q\) a lock request (in either mode) by transaction \(t\) on item \(x\), there is a position \(r > q\) at which \(s\) has a release by \(t\) of \(x\).

    In particular, transactions end holding no locks.

    def ReleasesLocks (s : List (Action n X)) : Prop :=
  ∀ (q : ℕ) (t : Fin n) (x : X) (m : LockMode), s[q]? = some (.lock t x m) →
    ∃ r, q < r ∧ s[r]? = some (.unlock t x)
    inductive Action (n : ℕ) (X : Type*)
  /-- A read or a write. -/
  | op (o : Op n X)
  /-- Transaction `t` acquires a lock on `x` in mode `m`. -/
  | lock (t : Fin n) (x : X) (m : LockMode)
  /-- Transaction `t` releases its lock on `x`. -/
  | unlock (t : Fin n) (x : X)

    DefinitionWell-formed locked schedules#✓fully proved

    Cslib.Databases.WellFormed

    A locked schedule \(s\) (a list of reads, writes, lock requests and lock releases of transactions) is well formed when its accesses are covered by locks and it releases its locks: every read or write in \(s\) is preceded by a lock request of its own transaction on its item, in a mode covering the access (shared or exclusive for a read, exclusive for a write), with no release of that item by that transaction in between; and every lock request in \(s\) by a transaction on an item is followed later in \(s\) by a release of that item by the same transaction.

    def WellFormed (s : List (Action n X)) : Prop := LocksCover s ∧ ReleasesLocks s

    DefinitionLock compatibility at a point#✓fully proved

    Cslib.Databases.LegalAt

    A locked schedule \(s\) is legal just before position \(p\) when, for every data item \(x\), all distinct transactions \(t \ne t'\) and all lock modes \(m\), \(m'\): if \(t\) holds a lock on \(x\) covering \(m\) and \(t'\) holds a lock on \(x\) covering \(m'\) just before position \(p\) of \(s\), then \(m\) and \(m'\) are both the shared mode. In words, two transactions do not both hold locks on the same item unless both locks are shared.

    def LegalAt (s : List (Action n X)) (p : ℕ) : Prop :=
  ∀ x t t' m m', t ≠ t' → HoldsBefore s t x m p → HoldsBefore s t' x m' p →
    m = .shared ∧ m' = .shared

  | op (o : Op n X)

    DefinitionLegal locked schedule#✓fully proved

    Cslib.Databases.Legal

    A locked schedule \(s\) of length \(\ell\) is legal when it satisfies lock compatibility at every point \(p \le \ell\): just before position \(p\), no two distinct transactions both hold locks on the same item unless both locks are shared.

    After the last action the locks no longer change, so the points \(p \le \ell\) are all the points.

    def Legal (s : List (Action n X)) : Prop := ∀ p ≤ s.length, LegalAt s p

    DefinitionTwo-phase schedules#✓fully proved

    Cslib.Databases.TwoPhase

    A locked schedule \(s\) is two-phase when every lock request of a transaction precedes every release of that transaction: whenever \(s\) has at position \(p\) a release by transaction \(t\) and at position \(q\) a lock request by \(t\) (on any items, in any mode), then \(q < p\).

    def TwoPhase (s : List (Action n X)) : Prop :=
  ∀ (t : Fin n) (p q : ℕ) (x y : X) (m : LockMode),
    s[p]? = some (.unlock t x) → s[q]? = some (.lock t y m) → q < p
    inductive Action (n : ℕ) (X : Type*)
  /-- A read or a write. -/
  | op (o : Op n X)
  /-- Transaction `t` acquires a lock on `x` in mode `m`. -/
  | lock (t : Fin n) (x : X) (m : LockMode)
  /-- Transaction `t` releases its lock on `x`. -/
  | unlock (t : Fin n) (x : X)
deriving DecidableEq

    DefinitionStrict two-phase schedules#✓fully proved

    Cslib.Databases.StrictTwoPhase

    A locked schedule \(s\) is strict two-phase when it is two-phase and every transaction releases its exclusive locks only after its last read or write: whenever \(s\) has at position \(p\) a release by transaction \(t\) of item \(x\) and just before position \(p\) transaction \(t\) holds an exclusive lock on \(x\), every read or write of \(t\) in \(s\) occurs at a position before \(p\).
