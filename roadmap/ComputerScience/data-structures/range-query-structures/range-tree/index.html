    A one-dimensional range tree over the integers is either empty, a single leaf holding an integer, or a binary node made of two integers \(l\) and \(h\) together with a left and a right subtree.     Cslib.Algorithms.Lean.RangeTree.toListAux

    For a range tree \(t\) and a list \(a\) of integers, \(\operatorname{aux}(t, a)\) is \(a\) if \(t\) is empty, the list \(x\) followed by \(a\) if \(t\) is a single leaf with value \(x\), and \(\operatorname{aux}(L, \operatorname{aux}(R, a))\) if \(t\) is a node with left subtree \(L\) and right subtree \(R\).

    Equivalently, \(\operatorname{aux}(t, a)\) is the leaf list of \(t\) followed by \(a\), so the leaf list is computed in linear time rather than by repeatedly appending left leaf lists.

  | .leaf x, acc => x :: acc
  | .node _ _ left right, acc => toListAux left (toListAux right acc)

    InductiveBounds-valid range trees#✓fully proved

    Cslib.Algorithms.Lean.RangeTree.BoundsOk

    For a range tree \(s\), write \(s_{\min}\) and \(s_{\max}\) for its cached lower and upper bounds: the stored interval endpoints at a node, the value itself at a leaf, and \(0\) for the empty tree. Bounds-validity is defined inductively: the empty tree and every leaf are bounds-valid, and a node with cached interval \([a, b]\), left child \(\ell\) and right child \(r\) is bounds-valid when \(\ell\) and \(r\) are bounds-valid, each of them has at least one leaf, \(a = \min(\ell_{\min}, r_{\min})\) and \(b = \max(\ell_{\max}, r_{\max})\).

    The children must be nonempty because the empty tree has cached bounds \(0\): with an empty child the node cache would only enclose the leaves (a node over an empty child and the single leaf \(5\) could cache \([0, 5]\)), not equal their true interval. In a bounds-valid tree every leaf value lies in the cached interval, and if the tree has a leaf, both cached bounds are leaf values.

    inductive BoundsOk : RangeTree → Prop where
  | empty : BoundsOk .empty
  | leaf (x : Int) : BoundsOk (.leaf x)
  | node {lo hi : Int} {left right : RangeTree} (hLeft : BoundsOk left)
      (hRight : BoundsOk right) (hLeftNe : left.toList ≠ [])
      (hRightNe : right.toList ≠ []) (hlo : lo = min left.tmin right.tmin)
      (hhi : hi = max left.tmax right.tmax) :
      BoundsOk (.node lo hi left right)
    inductive RangeTree where
  | empty : RangeTree
  | leaf : Int → RangeTree
  | node : Int → Int → RangeTree → RangeTree → RangeTree

    DefinitionAccumulator range report#✓fully proved

    Cslib.Algorithms.Lean.RangeTree.reportAux

    For integers \(a\), \(b\) and a list \(\mathit{acc}\) of integers, the accumulator range report of a range tree for \([a, b]\) starting from \(\mathit{acc}\) is defined by recursion on the tree. The empty tree returns \(\mathit{acc}\). A leaf with value \(x\) returns \(x\) followed by \(\mathit{acc}\) if \(a \le x \le b\), and \(\mathit{acc}\) otherwise. A node with cached interval \([l, h]\) returns \(\mathit{acc}\) if \(h < a\) or \(b < l\); otherwise, if \(a \le l\) and \(h \le b\), it returns the node's leaf values from left to right followed by \(\mathit{acc}\); otherwise it returns the report of the left child starting from the report of the right child starting from \(\mathit{acc}\).

    The cached bounds make each pruning test constant-time.

    def reportAux : RangeTree → Int → Int → List Int → List Int
  | .empty, _, _, acc => acc
  | .leaf x, lo, hi, acc => if lo ≤ x ∧ x ≤ hi then x :: acc else acc
  | .node nlo nhi left right, lo, hi, acc =>
      if nhi < lo ∨ hi < nlo then acc
      else if lo ≤ nlo ∧ nhi ≤ hi then
        toListAux (.node nlo nhi left right) acc
      else reportAux left lo hi (reportAux right lo hi acc)
    inductive RangeTree where
  | empty : RangeTree
  | leaf : Int → RangeTree
  | node : Int → Int → RangeTree → RangeTree → RangeTree
