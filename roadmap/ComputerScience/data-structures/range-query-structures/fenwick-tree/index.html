    StructureFenwick tree#✓fully proved

    Cslib.Algorithms.Lean.FenwickTree

    A Fenwick tree (binary indexed tree) over a commutative additive monoid \(\alpha\) is an array of elements of \(\alpha\), read as one-indexed interval sums with an unused dummy entry at index \(0\). The structure itself imposes no condition on the entries, and the underlying array it represents is not stored; the relation saying that a tree represents a given array is defined separately.

    public structure FenwickTree (α : Type u) [AddCommMonoid α] where
  /-- The one-indexed stored interval sums, with a dummy entry at index `0`,
  backed by an `Array` for constant-time reads; writes are constant-time
  only when the array is uniquely referenced (a shared array is copied
  first). -/
  bit : Array α

    Cslib.Algorithms.Lean.FenwickTree.lowbit

    For a natural number \(n > 0\), \(\operatorname{lowbit}(n)\) is the largest power of two dividing \(n\); for \(n = 0\) it is defined as \(\operatorname{lowbit}(0) = 0\).

    public def lowbit (n : Nat) : Nat :=
  if n = 0 then 0 else lowbitAux n n

  | 0, _ => 1
  | fuel + 1, n => if n % 2 = 1 then 1 else 2 * lowbitAux fuel (n / 2)

    Cslib.Algorithms.Lean.FenwickTree.blockSum

    For a list \(a\) of elements of a commutative additive monoid \(\alpha\) and a natural number \(j\), the interval sum at the one-indexed position \(j\) is the sum of the \(\operatorname{lowbit}(j)\) entries of \(a\) ending at zero-indexed position \(j - 1\), where \(\operatorname{lowbit}(j)\) is the largest power of two dividing \(j\) (with \(\operatorname{lowbit}(0) = 0\)) and entries past the end of \(a\) count as \(0\).

  ((List.range' (j - lowbit j) (lowbit j)).map (fun i => arr.getD i 0)).sum

    DefinitionFenwick tree representing a list#✓fully proved

    Cslib.Algorithms.Lean.FenwickTree.Valid

    A Fenwick tree \(t\) over an additive commutative monoid represents a list \(a\) of length \(n\) when its stored array has length \(n + 1\) (a dummy entry at index \(0\) plus one entry per element of \(a\)) and, for every \(j\) with \(1 \le j \le n\), the stored entry at index \(j\) equals the block sum of \(a\) at \(j\): the sum of the \(\operatorname{lowbit}(j)\) entries of \(a\) ending at position \(j - 1\) (positions counted from \(0\)), where \(\operatorname{lowbit}(j)\) is the largest power of two dividing \(j\).

    The underlying list itself is not stored at runtime; it appears only in this specification relation.

    @[expose] public def Valid {α : Type u} [AddCommMonoid α] (t : FenwickTree α)
    (arr : List α) : Prop :=
  t.bit.size = arr.length + 1 ∧
    ∀ j, 1 ≤ j → j ≤ arr.length → t.bit.getD j 0 = blockSum arr j

    Cslib.Algorithms.Lean.FenwickTree.build

    For a list \(a\) of length \(n\) over a commutative additive monoid \(\alpha\), the Fenwick tree built from \(a\) stores the array of length \(n + 1\) whose entry at index \(0\) is \(0\) and whose entry at each one-indexed position \(j\) with \(1 \le j \le n\) is the sum of the \(\operatorname{lowbit}(j)\) entries of \(a\) ending at zero-indexed position \(j - 1\), where \(\operatorname{lowbit}(j)\) is the largest power of two dividing \(j\).

    The input is converted to an array once, so each entry read is constant-time and construction is \(O(n \log n)\).

    public def build {α : Type u} [AddCommMonoid α] (arr : List α) : FenwickTree α where
  bit :=
    let a := arr.toArray
    (0 :: (List.range arr.length).map
      (fun i => blockSumArray a (i + 1))).toArray

    Cslib.Algorithms.Lean.FenwickTree.prefixSum

    Let \(t\) be a Fenwick tree over an additive commutative monoid with \(n\) underlying entries, let \(k\) be a natural number and let \(m = \min(k, n)\). The prefix sum of length \(k\) of \(t\) is the sum of the stored entries of \(t\) at the positions \(j_0 = m\), \(j_{r+1} = j_r - \operatorname{lowbit}(j_r)\), taken for as long as \(j_r > 0\).

    DefinitionPoint update of a Fenwick tree#✓fully proved

    Cslib.Algorithms.Lean.FenwickTree.add

    Let \(t\) be a Fenwick tree over a commutative additive monoid \(\alpha\), let \(n\) be its size (the length of its stored array minus one), let \(i\) be a natural number and let \(\delta \in \alpha\). Adding \(\delta\) at underlying position \(i\) adds \(\delta\) to the stored entries at the one-indexed positions \(j_1 = i + 1\) and \(j_{k+1} = j_k + \operatorname{lowbit}(j_k)\), for as long as \(j_k \le n\), where \(\operatorname{lowbit}(j)\) is the largest power of two dividing \(j\); every other stored entry is left unchanged. In particular, if \(i \ge n\) the tree is unchanged.

    Each write is constant-time only when the stored array is uniquely referenced, since a shared array is copied by the first persistent write. The walk is fuelled by the size, which always suffices because the visited positions strictly increase.

    public def add {α : Type u} [AddCommMonoid α] (t : FenwickTree α) (i : Nat)
    (δ : α) : FenwickTree α where
