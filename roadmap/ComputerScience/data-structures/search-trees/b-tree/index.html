    A raw B-tree with keys in a type \(\alpha\) is either a leaf, holding a list of keys, or an internal node, holding a list of separator keys and a list of child raw B-trees.     DefinitionAccumulating flattening of a B-tree#✓fully proved

    Cslib.Algorithms.Lean.BTree.flattenAux

    Given a raw B-tree \(T\) and a list \(s\), this returns the inorder traversal of \(T\) followed by \(s\). For a leaf it is the leaf's key list followed by \(s\). For an internal node with separator keys \(k_1, \dots, k_m\) and children \(c_0, \dots, c_n\) it is the sequence \(c_0, k_1, c_1, k_2, \dots\), in which children and keys alternate starting with a child until one of the two lists runs out, then the remaining keys or children in order, and finally \(s\); each key contributes itself, and each child contributes its own accumulating flattening with everything after it as the suffix. In particular every key of the tree occurs in the result.

    The result is built from right to left, so each key is copied only once.

    public def flattenAux : BTree α → List α → List α
  | .leaf keys, suffix => keys ++ suffix
  | .node keys children, suffix => flattenListAux keys children suffix
where
  flattenListAux : List α → List (BTree α) → List α → List α
    | [], [], suffix => suffix
    | [], child :: children, suffix =>
        flattenAux child (flattenListAux [] children suffix)
    | key :: keys, [], suffix => key :: flattenListAux keys [] suffix
    | key :: keys, child :: children, suffix =>
        flattenAux child (key :: flattenListAux keys children suffix)
    public inductive BTree (α : Type u) where
  | leaf (keys : List α) : BTree α
  | node (keys : List α) (children : List (BTree α)) : BTree α

    DefinitionInorder flattening of a B-tree#✓fully proved

    Cslib.Algorithms.Lean.BTree.flatten

    The flattening of a raw B-tree is the list of its keys defined recursively: for a leaf it is the leaf's key list, and for an internal node with keys \(k_1, k_2, \dots\) and children \(c_1, c_2, \dots\) it is the flattening of \(c_1\), then \(k_1\), then the flattening of \(c_2\), then \(k_2\), and so on, alternating while both lists last; whatever remains of the longer list is then appended in order, each surplus child contributing its flattening and each surplus key contributing itself. In particular every key of the tree occurs in the flattening.

    The flattening is computed in linear time by an accumulator-passing auxiliary function.

    public def flatten (tree : BTree α) : List α :=
  flattenAux tree []

    InductiveStructural invariant of a B-tree#✓fully proved

    Cslib.Algorithms.Lean.BTree.Valid

    For a minimum degree \(t\) and a minimum key count \(m\) for the top node, the invariant is defined inductively over the height: a leaf with \(k\) keys satisfies it at height \(0\) when \(m \le k \le 2t - 1\), and for every natural number \(h\), an internal node with \(k\) keys satisfies it at height \(h + 1\) when \(m \le k \le 2t - 1\), the node has exactly \(k + 1\) children, and every child satisfies the invariant with minimum key count \(t - 1\) at height \(h\). Here \(2t - 1\) and \(t - 1\) are truncated at \(0\).

    Consequently all leaves of a valid tree sit at the same depth, every node has at most \(2t - 1\) keys, and every node other than the top one has at least \(t - 1\) keys. Non-root trees are used with \(m = t - 1\); the root of a B-tree satisfies the root invariant instead.

    public inductive Valid (t : Nat) : Nat → Nat → BTree α → Prop where
  | leaf {mink : Nat} {keys : List α} (hlo : mink ≤ keys.length)
      (hhi : keys.length ≤ 2 * t - 1) : Valid t mink 0 (.leaf keys)
  | node {mink height : Nat} {keys : List α} {children : List (BTree α)}
      (hlo : mink ≤ keys.length) (hhi : keys.length ≤ 2 * t - 1)
      (hlen : children.length = keys.length + 1)
      (hchildren : ∀ child ∈ children, Valid t (t - 1) height child) :
      Valid t mink (height + 1) (.node keys children)
