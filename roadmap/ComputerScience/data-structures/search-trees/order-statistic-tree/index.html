    Cslib.Algorithms.Lean.OrderStatisticTree.CacheCorrect

    An order-statistic tree has correct size caches when, at every node, the cached subtree size equals the number of nodes of the left subtree plus the number of nodes of the right subtree plus one, that is, the number of nodes of the subtree rooted at that node.     Inserting a key \(k\) of a linearly ordered type into the empty tree gives a single node with key \(k\) and cached size \(1\).     DefinitionRank in an order-statistic tree#✓fully proved

    Cslib.Algorithms.Lean.OrderStatisticTree.rank

    For a key \(q\) of a linearly ordered type, the rank of \(q\) in an order-statistic tree is computed by descending from the root. It is \(0\) for the empty tree. At a node with key \(k\), left subtree \(L\) and right subtree \(R\), it is the rank of \(q\) in \(L\) if \(q < k\); it is \(s(L) + 1\) plus the rank of \(q\) in \(R\) if \(k < q\); and it is \(s(L)\) if \(q = k\). Here \(s(L)\) is the subtree size cached at the root of \(L\), and \(0\) if \(L\) is empty.

    When the cached sizes are correct and the tree is ordered, this is the number of keys in the tree strictly smaller than \(q\).

    public def rank {α : Type u} [LinearOrder α] (query : α) : Tree α → Nat
  | .nil => 0
  | .node entry left right =>
      if query < entry.key then rank query left
      else if entry.key < query then cachedSize left + 1 + rank query right
      else cachedSize left
    public abbrev Tree (α : Type u) := BinaryTree (Entry α)

    DefinitionSelect in an order-statistic tree#✓fully proved

    Cslib.Algorithms.Lean.OrderStatisticTree.select

    For an order-statistic tree \(T\) and a natural number \(i\), select at index \(i\) in \(T\) is computed by descending from the root. It returns nothing for the empty tree. At a node with key \(k\), left subtree \(L\) and right subtree \(R\), it is select at index \(i\) in \(L\) if \(i < s(L)\); it returns \(k\) if \(i = s(L)\); and it is select at index \(i - s(L) - 1\) in \(R\) if \(i > s(L)\). Here \(s(L)\) is the subtree size cached at the root of \(L\), and \(0\) if \(L\) is empty.

    When the cached sizes are correct, this returns the key at zero-based position \(i\) of the inorder traversal, and nothing if \(T\) has at most \(i\) nodes.

  | .nil, _ => none
  | .node entry left right, index =>
      if index < cachedSize left then select left index
      else if index = cachedSize left then some entry.key
      else select right (index - cachedSize left - 1)
