    Cslib.Algorithms.Lean.SplayTree.splay

    Let \(\alpha\) be a linearly ordered type and write \((k; L, R)\) for the binary tree with root key \(k\), left subtree \(L\) and right subtree \(R\). For \(x \in \alpha\), the splay \(S_x(t)\) of a binary tree \(t\) with keys in \(\alpha\) is defined by recursion on \(t\). The empty tree splays to itself, and \(t = (k; L, R)\) is left unchanged if \(x = k\), if \(x < k\) and \(L\) is empty, or if \(x > k\) and \(R\) is empty. If \(x < k\) and \(L = (a; A, B)\), then: if \(x = a\), the result is the zig \((a; A, (k; B, R))\); if \(x < a\) and \(S_x(A) = (d; A_1, A_2)\), the result is the zig-zig \((d; A_1, (a; A_2, (k; B, R)))\); if \(x > a\) and \(S_x(B) = (d; B_1, B_2)\), the result is the zig-zag \((d; (a; A, B_1), (k; B_2, R))\); and if the splayed subtree \(S_x(A)\), respectively \(S_x(B)\), is empty, the result is the zig \((a; A, (k; B, R))\). The case \(x > k\) with \(R = (b; C, D)\) is the mirror image: if \(x = b\), the result is the zig \((b; (k; L, C), D)\); if \(x > b\) and \(S_x(D) = (d; D_1, D_2)\), it is the zig-zig \((d; (b; (k; L, C), D_1), D_2)\); if \(x < b\) and \(S_x(C) = (d; C_1, C_2)\), it is the zig-zag \((d; (k; L, C_1), (b; C_2, D))\); and if the splayed subtree is empty, it is the zig \((b; (k; L, C), D)\).

    The search path for \(x\) runs from the root to the node with key \(x\), or to the last node visited if \(x\) is absent. Each recursive step consumes two edges of this path, starting at the root, so when the path has an odd number of edges the single rotation is performed on its last edge, the one farthest from the root.

    BinaryTree α → BinaryTree α
  | .nil => .nil
  | .node k l r =>
      if x = k then .node k l r
      else if x < k then
        match l with
        | .nil => .node k l r

              .node lk ll (.node k lr r)

    Cslib.Algorithms.Lean.SplayTree.split

    Let \(\alpha\) be a linearly ordered type, let \(x \in \alpha\), and write \((k; L, R)\) for the binary tree with root key \(k\), left subtree \(L\) and right subtree \(R\). The split of a binary tree with keys in \(\alpha\) at \(x\) is the pair of trees defined by recursion: the empty tree splits into two empty trees; if \(x < k\) and \(L\) splits into \((L_1, L_2)\), then \((k; L, R)\) splits into \((L_1, (k; L_2, R))\); if \(k < x\) and \(R\) splits into \((R_1, R_2)\), then \((k; L, R)\) splits into \(((k; L, R_1), R_2)\); and if \(x = k\), then \((k; L, R)\) splits into \((L, R)\).

    When the tree is a binary search tree (at every node, the keys of the left subtree are strictly smaller and those of the right subtree strictly larger than the node's key), the first part holds the keys below \(x\) and the second part the keys above \(x\); the key \(x\), if present, is dropped.

    public def split {α : Type u} [LinearOrder α] (x : α) :
    BinaryTree α → BinaryTree α × BinaryTree α
  | .nil => (.nil, .nil)
  | .node k l r =>
      if x < k then
        match split x l with
        | (ll, lr) => (ll, .node k lr r)
      else if k < x then
        match split x r with
        | (rl, rr) => (.node k l rl, rr)
      else (l, r)

    For a key \(x\) and a binary tree \(t\) over a linearly ordered type, inserting \(x\) into \(t\) splays \(x\) in \(t\), splits the resulting tree at \(x\) into a left part and a right part, and returns the tree whose root key is \(x\), whose left subtree is the left part and whose right subtree is the right part.
