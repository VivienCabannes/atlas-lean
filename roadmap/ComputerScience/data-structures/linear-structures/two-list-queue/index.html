    Cslib.Algorithms.Lean.Queue.Amortized.dequeue

    Dequeueing from a two-list queue \(q\) returns the next element in first-in, first-out order together with the remaining queue, or returns no element together with \(q\) itself when \(q\) is empty. In both cases the recorded cost is the modeled dequeue cost of \(q\).

    DefinitionOne step of a queue operation#✓fully proved

    Cslib.Algorithms.Lean.Queue.Amortized.step

    For a queue \(q\), an enqueue operation with value \(v\) performs the costed enqueue of \(v\) onto \(q\). A dequeue operation performs the costed dequeue of \(q\) and keeps the remaining queue and the cost, discarding the removed value; on an empty queue the remaining queue is \(q\) itself.

    def step (q : Std.Queue α) : Operation α → TimeM Nat (Std.Queue α)
  | .enqueue value => enqueue q value
  | .dequeue =>
      let result := dequeue q
      ⟨result.ret.2, result.time⟩
    inductive Operation (α : Type u) where
  | enqueue (value : α)

    DefinitionRunning a sequence of queue operations#✓fully proved

    Cslib.Algorithms.Lean.Queue.Amortized.run

    Running a list of queue operations from a queue \(q\) performs the operations one step at a time from left to right, starting at \(q\). The result is the final queue, and the cost is the sum of the costs of the individual steps; running the empty list returns \(q\) at cost \(0\).

    def run : List (Operation α) → Std.Queue α → TimeM Nat (Std.Queue α)
  | [], q => ⟨q, 0⟩
  | op :: ops, q =>
      let first := step q op
      let rest := run ops first.ret
      ⟨rest.ret, first.time + rest.time⟩
    inductive Operation (α : Type u) where
  | enqueue (value : α)
  | dequeue
