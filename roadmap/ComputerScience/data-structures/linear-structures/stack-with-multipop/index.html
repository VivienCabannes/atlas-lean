    TheoremResult and cost of stack pop#✓fully proved

    Cslib.Algorithms.Lean.Stack.pop_eq

    Let \(s\) be a stack over a type \(\alpha\) (a list of elements of \(\alpha\) whose first element is the top). If \(s\) is empty, popping \(s\) returns underflow (no value) at cost \(0\). If \(s\) has top \(h\) and remaining stack \(t\), popping \(s\) returns the pair \((h, t)\) at cost \(1\).

    This holds for every type \(\alpha\); no element of \(\alpha\) is assumed to exist.

    theorem pop_eq {α : Type u} (stack : List α) :

    Cslib.Algorithms.Lean.Stack.operations_spec

    Let \(\alpha\) be a type, let \(s\) be a stack over \(\alpha\) (a list of elements of \(\alpha\) whose first element is the top) and let \(v \in \alpha\). Pushing \(v\) onto \(s\) returns the stack with top \(v\) followed by the elements of \(s\), at cost \(1\). Popping \(s\) returns underflow (no value) at cost \(0\) if \(s\) is empty, and returns the pair \((h, t)\) at cost \(1\) if \(s\) has top \(h\) and remaining stack \(t\). Reading the top of \(s\) returns underflow (no value) at cost \(0\) if \(s\) is empty, and returns \(h\) at cost \(1\) if \(s\) has top \(h\).

    theorem operations_spec {α : Type u} (stack : List α) (value : α) :
    push stack value = ⟨value :: stack, 1⟩ ∧
    pop stack = (match stack with
      | [] => ⟨none, 0⟩
      | head :: tail => ⟨some (head, tail), 1⟩) ∧
    top stack = (match stack with
      | [] => ⟨none, 0⟩
      | head :: _ => ⟨some head, 1⟩)

    Cslib.Algorithms.Lean.Stack.multipop

    For a stack \(S\), stored as a list with its top first, and a natural number \(k\), MULTIPOP of \(S\) with count \(k\) repeatedly removes the top element while the stack is nonempty and fewer than \(k\) elements have been removed, and returns the remaining stack. Each removed element costs one unit, and nothing else is charged.

    This is MULTIPOP from CLRS, fourth edition, Section 16.1.

    public def multipop {α : Type u} : List α → Nat → TimeM Nat (List α)
  | stack, 0 => pure stack
  | [], _ + 1 => pure []
  | _ :: tail, k + 1 => do
    TimeM.tick 1
    multipop tail k

    DefinitionRunning a sequence of stack operations#✓fully proved

    Cslib.Algorithms.Lean.Stack.execute

    Given a stack \(S\) and a finite sequence of operations, each a PUSH of a value, a POP or a MULTIPOP with an integer count, the operations are applied to \(S\) in order. PUSH of \(x\) puts \(x\) on top at cost \(1\); POP removes the top element at cost \(1\); MULTIPOP with count \(k\) is MULTIPOP with an integer count, costing one unit per element removed. If a POP meets an empty stack, the run stops and reports an error, that POP is not charged, and the cost is that of the operations before it. Otherwise the run returns the final stack, and its cost is the sum of the costs of all operations.

    public def execute {α : Type u} : List α → List (Operation α) → TimeM Nat (Option (List α))
  | stack, [] => pure (some stack)
  | stack, .push value :: ops => do
    TimeM.tick 1
    execute (value :: stack) ops
  | [], .pop :: _ => pure none
  | _ :: tail, .pop :: ops => do
    TimeM.tick 1
    execute tail ops
  | stack, .multipop count :: ops => do
    let next ← multipopSigned stack count
    execute next ops
    public inductive Operation (α : Type u) where
  | push (value : α)
  | pop
  | multipop (count : Int)
deriving Repr

    TheoremRunning a POP agrees with the standalone POP#✓fully proved

    Cslib.Algorithms.Lean.Stack.execute_pop_eq_bind_pop

    For every stack \(S\) and every finite sequence \(\sigma\) of stack operations, running POP followed by \(\sigma\) on \(S\) has the same result and cost as first performing the standalone POP on \(S\) and then, if it reports underflow, stopping with an error at no further cost, or, if it removes the top element and leaves the stack \(S'\), running \(\sigma\) on \(S'\), the two costs being added.

    public theorem execute_pop_eq_bind_pop {α : Type u} (stack : List α)
    (ops : List (Operation α)) :
    execute stack (.pop :: ops) = (do
      let removed ← pop stack
      match removed with
      | none => pure none
      | some (_, next) => execute next ops)

    TheoremCost balance for stack operation sequences#✓fully proved

    Cslib.Algorithms.Lean.Stack.execute_balance

    For every stack \(S\) and every finite sequence \(\sigma\) of stack operations, if running \(\sigma\) on \(S\) succeeds with final stack \(F\), then the cost of the run plus the number of elements of \(F\) equals the number of elements of \(S\) plus twice the number of PUSH operations in \(\sigma\).

    public theorem execute_balance {α : Type u} (stack : List α) (ops : List (Operation α))
    (final : List α) (h : (execute stack ops).ret = some final) :
    (execute stack ops).time + final.length = stack.length +
      2 * ops.countP (fun op => match op with | .push _ => true | _ => false)
