    StructureCuckoo hash table#✓fully proved

    Cslib.Algorithms.Lean.CuckooHashing

    Given a type \(K\) of keys, a type \(V\) of values, a number \(m\) of slots, and two hash functions \(h_1, h_2 : K \to \{0, \dots, m - 1\}\), a cuckoo hash table consists of two tables, each a vector of \(m\) slots; every slot is either empty or holds a key–value pair \((k, v)\) with \(k \in K\) and \(v \in V\). The structure itself does not require a pair \((k, v)\) to sit at slot \(h_1(k)\) of the first table or at slot \(h_2(k)\) of the second.

    No expected constant-time bound is claimed because the model supplies neither a probability distribution nor an independence assumption about the hashes.

    public structure CuckooHashing (K : Type u) (V : Type v) (m : Nat)
    (h1 h2 : K → Fin m) where
  /-- The first table; key `k` may occupy slot `h1 k`. -/
  table1 : Vector (Option (K × V)) m
  /-- The second table; key `k` may occupy slot `h2 k`. -/
  table2 : Vector (Option (K × V)) m

    DefinitionPlacement invariant of a cuckoo hash table#✓fully proved

    Cslib.Algorithms.Lean.CuckooHashing.Valid

    A cuckoo hash table with hash functions \(h_1, h_2\) satisfies the placement invariant when every pair \((k, v)\) in slot \(i\) of the first table has \(i = h_1(k)\), and every pair \((k, v)\) in slot \(i\) of the second table has \(i = h_2(k)\).

    This is what lets lookup check only two slots.

    public def Valid (table : CuckooHashing K V m h1 h2) : Prop :=
  (∀ (i : Fin m) (key : K) (value : V),
    table.table1.get i = some (key, value) → i = h1 key) ∧
    ∀ (i : Fin m) (key : K) (value : V),
      table.table2.get i = some (key, value) → i = h2 key

    Cslib.Algorithms.Lean.CuckooHashing.KeyDet

    A cuckoo hash table is key-deterministic when each key is stored with at most one value: for every key \(k\) and values \(v_1, v_2\), if the bindings \(k \mapsto v_1\) and \(k \mapsto v_2\) are both stored in the table, then \(v_1 = v_2\). Duplicate copies of the same pair are allowed.

    DefinitionCuckoo eviction loop#✓fully proved

    Cslib.Algorithms.Lean.CuckooHashing.insertAux

    The eviction loop takes a cuckoo hash table with hash functions \(h_1\) and \(h_2\), a key–value pair \((k, v)\), a choice of the first or second table, and a natural number as fuel, and either returns a table or fails. With fuel \(0\) it fails. With fuel \(n + 1\) and the first table chosen, it writes \((k, v)\) into slot \(h_1(k)\) of the first table; if that slot was empty it returns the resulting table, and otherwise it repeats on the resulting table with the evicted pair, the second table and fuel \(n\). With the second table chosen it does the same at slot \(h_2(k)\) of the second table and continues with the first table.

    Cslib.Algorithms.Lean.CuckooHashing.insertAux · 20 lines 
    def insertAux (table : CuckooHashing K V m h1 h2) (cur : K × V) (first : Bool) :
    Nat → Option (CuckooHashing K V m h1 h2)
  | 0 => none
  | fuel + 1 =>
      if first then
        match table.table1.get (h1 cur.1) with
        | none =>
            some ⟨table.table1.set (h1 cur.1).val (some cur) (h1 cur.1).isLt, table.table2⟩
        | some occ =>
            insertAux
              ⟨table.table1.set (h1 cur.1).val (some cur) (h1 cur.1).isLt, table.table2⟩
              occ false fuel
      else
        match table.table2.get (h2 cur.1) with
        | none =>
            some ⟨table.table1, table.table2.set (h2 cur.1).val (some cur) (h2 cur.1).isLt⟩
        | some occ =>
            insertAux
              ⟨table.table1, table.table2.set (h2 cur.1).val (some cur) (h2 cur.1).isLt⟩
              occ true fuel

    DefinitionCuckoo hash table lookup#✓fully proved

    Cslib.Algorithms.Lean.CuckooHashing.lookup

    For a cuckoo hash table \(T\) with hash functions \(h_1\) and \(h_2\) and a key \(k\), the lookup of \(k\) in \(T\) returns \(v\) if slot \(h_1(k)\) of the first table holds a pair \((k, v)\); otherwise it returns \(v\) if slot \(h_2(k)\) of the second table holds a pair \((k, v)\); otherwise it returns nothing. No other slot is examined.

    public def lookup (table : CuckooHashing K V m h1 h2) (key : K) : Option V :=
  match table.table1.get (h1 key) with
  | some (k₁, v₁) =>
      if k₁ = key then some v₁
      else
        match table.table2.get (h2 key) with
        | some (k₂, v₂) => if k₂ = key then some v₂ else none
        | none => none
  | none =>
      match table.table2.get (h2 key) with
      | some (k₂, v₂) => if k₂ = key then some v₂ else none
      | none => none

    TheoremCuckoo lookup finds every stored key#✓fully proved

    Cslib.Algorithms.Lean.CuckooHashing.lookup_isSome_of_stored

    Let \(T\) be a cuckoo hash table with hash functions \(h_1\) and \(h_2\) that satisfies the placement invariant, and let \(k\) be a key and \(v\) a value. If the binding \(k \mapsto v\) is stored in some slot of either table of \(T\), then looking up \(k\) in \(T\) returns some value.

    The returned value may differ from \(v\) when \(k\) is stored with two different values; when \(T\) stores each key with at most one value, it is \(v\).

    public theorem lookup_isSome_of_stored (table : CuckooHashing K V m h1 h2)
